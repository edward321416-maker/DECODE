## Read and handoff order

Follow [Project Operating Manual](PROJECT_OPERATING_MANUAL.md) for the canonical read order and precedence. In summary:

1. Read [CURRENT_STATUS](CURRENT_STATUS.md), [DECISIONS](DECISIONS.md) and [PUBLICATION_POLICY](PUBLICATION_POLICY.md).
2. Product records approved scope and acceptance criteria in [CHATGPT_TO_CODEX](../handoff/CHATGPT_TO_CODEX.md).
3. Engineering implements only the requested scope and updates [CODEX_TO_CHATGPT](../handoff/CODEX_TO_CHATGPT.md), evidence and any actually executed experiment log.
4. Review the actual diff (method per [COLLABORATION_RULES](COLLABORATION_RULES.md)), validate affected scope and conflicts, and integrate verified rules/results into main. Product records the next decision with the reviewed revision.

Direct user decisions override older planning proposals. Assistant proposals are source material, not independent authorization. LOCK CANDIDATE items require explicit Product approval to become LOCKED.
